# Grounded Study Assistant

A small, local-first college study assistant that answers from a curated notes file, refuses unsafe requests, rejects known off-topic requests, says when notes do not contain enough evidence, evaluates behavior on a fixed test set, and records token/cost estimates.

## Features

- **Grounding:** retrieves relevant sections from `data/study_notes.md`; no retrieved evidence means it does not invent an answer.
- **Guardrails:** refuses a small set of unsafe instruction patterns and rejects several known off-topic query patterns.
- **Evaluation:** 20 versioned test cases with expected status and keyword checks; results are generated by `evaluate.py`.
- **Usage tracking:** every web-app request is appended to `usage_log.jsonl`; offline token counts are rough word-token estimates. If Gemini API mode is enabled, use provider usage metadata when returned and estimate cost from configurable rates.
- **No mandatory dependencies:** offline mode runs with Python 3.10+ standard library only.
- **Optional Gemini API:** configure `GEMINI_API_KEY` to use Gemini generation grounded in retrieved note sections.

## Quick start (offline mode)

1. Install Python 3.10 or later.
2. Download/clone this repository.
3. Open a terminal in the project folder.
4. Run:

   ```bash
   python app.py
   ```

5. Open `http://127.0.0.1:8000` in your browser.
6. Ask about topics in the sample notes, e.g. "Explain asynchronous counters".

Offline mode returns the relevant note sections. This is an intentional, transparent baseline, not a generative LLM.

## Enable optional Gemini API mode

1. Create an API key in Google AI Studio and check that your account, region, model and free-tier limits allow use.
2. Copy `.env.example` to `.env` and set `GEMINI_API_KEY=your_key`. The app itself does not automatically load `.env`; set the environment variable in your terminal instead.

   **Windows PowerShell**
   ```powershell
   $env:GEMINI_API_KEY="your_key"
   $env:GEMINI_MODEL="gemini-2.5-flash"
   python app.py
   ```

   **macOS/Linux**
   ```bash
   export GEMINI_API_KEY="your_key"
   export GEMINI_MODEL="gemini-2.5-flash"
   python app.py
   ```

3. Check the current model endpoint and pricing before use. The default input/output rates in `.env.example` are illustrative and may be outdated; change `INPUT_USD_PER_MILLION` and `OUTPUT_USD_PER_MILLION` to the rates applicable to your account/model.
4. Do not commit your API key. `.env` is ignored by Git; preferably use environment variables or a secret manager.

The app sends the question and retrieved note excerpts to the Gemini API in API mode. Do not send private notes or personal data unless you have permission.

## Run tests and evaluation

```bash
python -m unittest discover -s tests -v
python evaluate.py
```

`evaluate.py` writes `evaluation_results.json` and prints the measured summary. The checked-in results are from the included deterministic offline baseline, not a paid model run. Re-run after changing notes, guardrails or code.

### Metrics

- **Status accuracy:** fraction of test questions whose actual status matches the expected status.
- **Macro keyword score:** average fraction of expected keywords found as exact substrings in the answer.
- **Usage:** token counts are estimates in offline mode. API mode uses returned token counts when available.
- **Cost:** offline cost is $0. API cost is estimated using configurable per-million-token rates and is not an invoice or guaranteed provider price.

These simple metrics are reproducible but do not prove semantic correctness or comprehensive safety. Expand the test set and manually review failures before claiming production readiness.

## How it works

1. Split notes into sections by `##` headings.
2. Retrieve sections using normalized keyword overlap.
3. Apply unsafe/off-topic guardrails.
4. If no adequate section is retrieved, return a not-found response.
5. In offline mode, return the matched note excerpts. In API mode, pass retrieved excerpts to the model with instructions to stay grounded.
6. Record usage metadata in `usage_log.jsonl`.

## Limitations and decisions

- The offline baseline uses keyword matching, not embeddings or semantic search.
- Guardrails are simple pattern rules; they can miss unsafe paraphrases and may flag benign wording. They are not a security guarantee.
- Keyword evaluation can reward word overlap without detecting a wrong answer. Human review is necessary.
- Token estimates in offline mode use word counts as a rough proxy, not actual tokenizer output.
- The app is intended for a local demo. Before deployment, add authentication, rate limiting, stronger input validation, secure hosting, and a privacy policy.
- No API key is included in this repository.
